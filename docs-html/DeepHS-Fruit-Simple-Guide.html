二、遇到的问题及修复

问题 1：sklearn plot_confusion_matrix 导入错误

错误：ImportError: cannot import name 'plot_confusion_matrix'

原因：scikit-learn 1.2+ 移除了该函数

修复文件：classification/utils/confusion_matrix.py

# 修改前
from sklearn.metrics import plot_confusion_matrix, confusion_matrix, ConfusionMatrixDisplay

# 修改后
from sklearn.metrics import confusion_matrix, ConfusionMatrixDisplay

问题 2：pytorch_lightning seed_everything API 变化

错误：AttributeError: module 'pytorch_lightning.utilities.seed' has no attribute 'seed_everything'

修复文件：classification/train.py（约第415行）

# 修改前
lightning.utilities.seed.seed_everything(seed)

# 修改后
lightning.seed_everything(seed)

问题 3 & 4：validation_epoch_end 和 test_epoch_end 被移除

错误：NotImplementedError: Support for `validation_epoch_end` has been removed

修复文件：classification/train.py

# 修改前
def validation_epoch_end(self, outputs):
    ...

def test_epoch_end(self, outputs):
    outputs = self.all_gather(outputs)
    ...

# 修改后
def on_validation_epoch_end(self):
    ...

def on_test_epoch_end(self):
    if hasattr(self, 'test_step_outputs'):
        outputs = self.all_gather(self.test_step_outputs)
        ...
        self.test_step_outputs.clear()

# 同时需要在 __init__ 中添加：
self.test_step_outputs = []

# 在 test_step 中添加：
self.test_step_outputs.append(output)

问题 5：DDP 分布式训练在 Windows 单卡上失败

错误：torch.distributed.init_process_group 连接失败

修复文件：classification/train.py（Trainer 初始化）

# 修改前
trainer = lightning.Trainer(
    max_epochs=opt.num_epochs,
    accelerator='gpu',
    devices=-1,
    strategy='ddp',
    ...
)

# 修改后
trainer = lightning.Trainer(
    max_epochs=opt.num_epochs,
    accelerator='gpu',
    devices=1,
    strategy='auto',
    ...
)

问题 6：Windows 多进程内存错误

错误：MemoryError (multiprocessing)

修复文件：classification/train.py

# 修改前
hparams['num_workers'] = 4 if not hparams['debug'] else 0

# 修改后
import platform
if platform.system() == 'Windows':
    hparams['num_workers'] = 0
else:
    hparams['num_workers'] = 4 if not hparams['debug'] else 0

问题 7：BatchNorm1d batch_size=1 错误

错误：ValueError: Expected more than 1 value per channel when training

修复文件：classification/models/deephs_net.py

# 修改前
self.fc = nn.Sequential(
    nn.Sigmoid(),
    nn.BatchNorm1d(hidden_layers[2]),
    nn.Linear(hidden_layers[2], num_classes),
)

# 修改后
self.fc = nn.Sequential(
    nn.Sigmoid(),
    nn.LayerNorm(hidden_layers[2]),
    nn.Linear(hidden_layers[2], num_classes),
)

python classification/train.py --data_path ./data --model deephs_net --fruit kaki --classification_type ripeness --seed 23312323 --num_epochs 200 --batch_size 16

五、训练结果

第一次训练（seed=42, epochs=50）

  • 训练集：280 样本
  • 验证集：12 样本
  • 测试集：12 样本
  • Best Val Loss：0.712（第18 epoch）
  • Test Accuracy：50%
  • Test Loss：1.32
结果分析：50% 准确率比随机猜测（33%）好一些，但远低于论文报告的 85-90%。可能原因：epoch 数太少、数据量小、验证/测试集太小。

各水果数据量对比

水果 总样本 有标签 标注率
Avocado 1,702 316 18.6%
Kiwi 1,522 262 17.2%
Kaki（柿子） 793 160 20.2%
Mango 1,124 160 14.2%
Papaya 548 120 21.9%

为什么只有部分样本有标签？

高光谱数据采集容易（只需拍照），但标注需要人工检查每个水果的实际状态，成本高、耗时长，所以只有约 15-22% 的样本有标签。
