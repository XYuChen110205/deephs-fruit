问题汇总表

# 问题 错误信息 修复文件
1 sklearn API 移除 ImportError: cannot import name 'plot_confusion_matrix' classification/utils/confusion_matrix.py
2 Lightning seed API 变化 AttributeError: module 'pytorch_lightning.utilities.seed' has no attribute 'seed_everything' classification/train.py
3 validation_epoch_end 移除 NotImplementedError: Support for `validation_epoch_end` has been removed classification/train.py
4 test_epoch_end 移除 NotImplementedError: Support for `test_epoch_end` has been removed classification/train.py
5 DDP 分布式训练错误 torch.distributed.init_process_group 连接失败 classification/train.py
6 Windows 多进程内存错误 MemoryError (multiprocessing) classification/train.py
7 BatchNorm1d batch_size=1 错误 ValueError: Expected more than 1 value per channel when training classification/models/deephs_net.py

详细修复方案

🔴 问题 1：sklearn plot_confusion_matrix 导入错误

原因：scikit-learn 1.2+ 移除了 plot_confusion_matrix 函数

修复文件：classification/utils/confusion_matrix.py

# 修改前（第1行） from sklearn.metrics import plot_confusion_matrix, confusion_matrix, ConfusionMatrixDisplay # 修改后 from sklearn.metrics import confusion_matrix, ConfusionMatrixDisplay

🔴 问题 2：pytorch_lightning seed_everything API 变化

原因：Lightning 2.0+ 改变了 seed_everything 的位置

修复文件：classification/train.py（约第415行）

# 修改前 lightning.utilities.seed.seed_everything(seed) # 修改后 lightning.seed_everything(seed)

🔴 问题 3 & 4：validation_epoch_end 和 test_epoch_end 被移除

原因：Lightning 2.0+ 移除了这些方法，改用 on_*_epoch_end

修复文件：classification/train.py

# 修改前 - validation_epoch_end def validation_epoch_end(self, outputs): ... # 修改后 def on_validation_epoch_end(self): ... # 修改前 - test_epoch_end def test_epoch_end(self, outputs): outputs = self.all_gather(outputs) ... # 修改后 def on_test_epoch_end(self): if hasattr(self, 'test_step_outputs'): outputs = self.all_gather(self.test_step_outputs) ... self.test_step_outputs.clear() # 同时需要在 __init__ 中添加： self.test_step_outputs = [] # 在 test_step 中添加： self.test_step_outputs.append(output)

🔴 问题 5：DDP 分布式训练在 Windows 单卡上失败

原因：Windows 不支持 DDP (Distributed Data Parallel)

修复文件：classification/train.py（Trainer 初始化部分）

# 修改前 trainer = lightning.Trainer( max_epochs=opt.num_epochs, accelerator='gpu', devices=-1, # 使用所有GPU strategy='ddp', # 分布式训练 ... ) # 修改后 trainer = lightning.Trainer( max_epochs=opt.num_epochs, accelerator='gpu', devices=1, # 只使用1个GPU strategy='auto', # 自动选择策略 ... )

🔴 问题 6：Windows 多进程内存错误

原因：Windows 上 num_workers > 0 会导致内存问题

修复文件：classification/train.py（main 函数中）

# 修改前 hparams['num_workers'] = 4 if not hparams['debug'] else 0 # 修改后 import platform if platform.system() == 'Windows': hparams['num_workers'] = 0 # Windows 上禁用多进程 else: hparams['num_workers'] = 4 if not hparams['debug'] else 0

🔴 问题 7：BatchNorm1d batch_size=1 错误

原因：BatchNorm1d 需要 batch_size > 1 才能计算统计量

修复文件：classification/models/deephs_net.py

# 修改前 self.fc = nn.Sequential( nn.Sigmoid(), nn.BatchNorm1d(hidden_layers[2]), # 需要 batch_size > 1 nn.Linear(hidden_layers[2], num_classes), ) # 修改后 self.fc = nn.Sequential( nn.Sigmoid(), nn.LayerNorm(hidden_layers[2]), # 对每个样本独立归一化 nn.Linear(hidden_layers[2], num_classes), )

各水果数据量对比

💡
为什么只有部分样本有标签？
- 高光谱数据采集容易（只需拍照）
- 但标注需要人工检查每个水果的实际状态（成熟度/硬度/糖度）
- 标注成本高、耗时长，所以只有约 15-22% 的样本有标签
- 三个分类任务（成熟度、硬度、糖度）的标签是独立的，一个样本可能只有其中一种标签
